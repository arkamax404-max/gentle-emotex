# gentle-emote v0.2.0

Release of the extension's external-display era: USB serial delivery to the LED panel, an interactive control panel with global appearance editing, a fully session-local D200 mirror, persistent manual avatar selection with two new emote sets, native ODD work phases and subagent counts on the display, and truthful display copy (`WORKING`) plus global PNG appearance ownership. GitHub Release and tag only — no npm publication.

## Highlights

| Area | What landed |
|------|-------------|
| USB serial output | `/emote usbOn [port]` delivers avatar frames to the LED panel over USB CDC (firmware wire protocol v1, stop-and-wait, optional `serialport` dependency) |
| Interactive panel | `/emote` opens a live-truth modal panel; size/placement/frame/accent become editable and write atomically to user-global config; per-destination clock mode is a session-local switch |
| D200 mirror | Fully session-local (state and port): every session and `/reload` starts off; legacy `output-states/d200.json` is ignored silently; `/emote d200On <port>` retargets for the session |
| Avatar selection | `/emote avatar <folder>` switches immediately and saves globally; `/emote avatar auto` restores mappings; new `gentleled` and `gentleemotex` emote sets ship |
| Native subagents + ODD phases | Real subagent task counts from the notification bus; eight detailed work phases shown natively (with frame previews) and via the explicit `gentle_odd_phase` tool fallback — the extension does not infer work phases automatically |
| Clocks and captions | Ticking `MM:SS` phase clock, experimental 5-minute idle clock (64×64, also for settled errors), project-name caption layout on every image destination |
| Commands | `/emote displayOn <address>`, `/emote status`, `/emote debugOn`/`debugOff` (diagnostic only), `/emote d200On <port>` |
| Policy | Global PNG appearance (`transparentBackground`, `background`, `backgroundCoverage`) is owned by extension defaults + user-global config only; physical LED/USB outputs always deliver opaque PNGs |

## Compatibility

- **Node.js >= 22.19.0** (package `engines`).
- Pi coding-agent host with extension support; keep the extension's `enabled: true`.
- USB output needs the optional `serialport` dependency (lazily imported); without it the command warns and every other output keeps working.
- Detailed ODD phases and subagent counts need Gentle Shell's native bus; on plain Pi hosts the phase fallback is the explicit `gentle_odd_phase` tool.
- LED/ESP32 HTTP delivery is unencrypted and unauthenticated; use trusted local networks. USB serial output uses the connected CDC device, not HTTP. The D200 focus contract (`DEDICATED-SUCCESS-v1`) needs a compatible receiver; receiver compatibility is required, not certified here.

## Known limits

- The existing shared store is inactive and POSIX-only. Active desktop integration and Windows write/durability support are not shipped in this release.
- Windows: the full local run is 638 passed / 34 failed — the failures come from POSIX appearance expectations and path normalization in the test suite; they are not fixed in this release.
- The D200 mirror persists nothing by design (session-local on/off and port).
- `/emote debugOn` is a diagnostic for unsupported-frame warnings; it is not the `localOn` switch and never enables an output.
- Diagnostics report PNG selection and published ODD phase side by side, never equated.
- No npm publication; the package is not released to the registry.
