# Emote control panel (plugin-owned)
An interactive panel inside gentle-emotex that manages every adjustable part of the extension, with no change to the gentle-shell package.
Branch: feat/emote-panel. Baseline: 7c39e54. The uncommitted idle-clock fix in the working tree stays part of this branch; no push, PR or release is authorized by this document.

## Specs
S1. "crees posible solo para gentle-shell que creemos un panel para gestionar la activacion y desactivacion de la salida de los avatares y lo que se pueda de todo lo referente a gentle-emotex ?" — the panel must cover output activation/deactivation and as much of the extension's surface as it can.
S2. "ok, porque no quiero desalinearme con las futuras actualizaciones de gentle-shell, asi que por lo tanto abrimos una feature para implementar el alcance lo mas completo posible" — the widest scope, implemented entirely in gentle-emotex; the gentle-shell repository and package stay untouched, so upstream updates never conflict with us.
S3. "antes de fijar el alcance dime si para hacer esto vamos a modificar el proyecto de gentle-shell o todo quedaría dentro de nuestro plugin" — answered: everything stays in the plugin. `ctx.ui.custom()` is public Pi extension API, so a full overlay needs no host cooperation.
S4. Recorded decision from S2/S3: no cross-package protocol and no edits to gentle-shell. The panel lives in this package, is invoked by our own command, and is inert unless invoked, so no host detection or gating is required.
S5. Owner rule for persistence, verbatim: "sobre t9 las opciones que solo tengan sentido a nivel sesion como el reloj serán locales, es resto que afectarían a todos los avatares en curso serán globales, teniendo en cuanta que el layout del display Led no se puede alterar y el d200 es una tecla de un stream deck asi que pocas fiestas ahí". Reading: the per-destination clock mode stays session-local; size, placement, frame and accent are written to the user-global config; LED layout keys (outline, background, backgroundCoverage) are out of scope, and the D200 gets no controls of its own.

L14. Recorded rule (S5): session-local keys are the ones that only make sense for this session — the per-destination `idleClock` mode; global keys are the ones that shape every avatar — `size`, `placement`, `frame`, `accent`, written to the user-global config of the agent directory the session actually runs on. The LED layout cannot be altered, so `outline`, `background` and `backgroundCoverage` are explicitly out of scope, and the D200 key gets no extra controls beyond mirroring the avatar. Writing global keys extends the AGENTS.md invariant "Commands never rewrite config.json — with one documented exception" to a second documented exception, with the same discipline as the existing one: atomic write, unrelated keys and other layers preserved, fail closed on an unreadable or non-object file, never touching project-local config, and never enabling an output.
L15. Correction worth stating before implementation: persisting a global key does NOT retroactively change sessions that are already running. Each process loads the configuration at `session_start` and the extension's code once at start, so the panel's global write reaches the current session immediately (it applies live) and every future session, while other live processes keep their loaded values until they `/reload` or restart. "Global" here means "persisted for every avatar from now on", not "broadcast to running sessions".
